# Code Simplifier

触发条件：写完一批代码修改后，用户说"简化一下"、"review 一下"、"检查代码"。

## 检查清单

1. **冗余代码**：未使用的变量、重复逻辑、多余注释
2. **命名**：变量/函数名是否清晰、一致
3. **复杂度**：过长的函数（>30 行）、深层嵌套（>3 层）
4. **性能**：不必要的循环、重复计算、大对象拷贝
5. **安全**：SQL 注入、XSS、命令注入风险

## 步骤

1. **运行 `git diff`** 获取本次改动
2. **逐文件 review**：对照上述清单检查
3. **标注问题**：在代码中用注释标注 `// REVIEW: <问题>`
4. **修复**：对于明确的问题直接修改
5. **验证**：检查修改后的代码还能编译/运行

## 输出格式

```markdown
## Code Review 结果

| 文件 | 问题数 | 已修复 | 需确认 |
|------|--------|--------|--------|
| xxx.cu | 3 | 2 | 1 |

### 具体问题
- `xxx.cu:42` — 循环内重复计算（已修复）
- `xxx.cu:78` — 变量命名不清晰（需确认）
```

## 规则

- 不确定的问题标记"需确认"，不要自作主张改业务逻辑
- 只 review 本次 `git diff` 中的改动，不扫全项目
